# Retained publisher review is admission's behavioral evidence

The standard owns pack construction and its source/form tools. The publisher runs the one customer life at the end
of construction and retains the independent outline and life plausibility verdicts beside it. Catalog admission
reads that result from the immutable published artifact. It never installs a candidate, imports its code, creates
a World, runs a client or browser, replays a journey, or measures a previous release.

The operator controller reads the submission at an exact PR head from a clean trusted base. It fetches the exact
registry archive and recomputes its SHA-512 integrity. The npm visibility endpoint determines the package's access;
no contributor field selects the trust rule. A public package requires cryptographically verified registered-source
Sigstore provenance. A restricted package binds the submission's registered source repository and immutable
`sourceCommit`, exact version and integrity under the existing authority checks. The commit must exist in that
registered repository. This uses the existing submission and authority record, with no new custody mechanism.
Safe ordinary archive members supply the package identity, declared dependency ranges,
generated vendor facts, README, outline, nonempty customer life and two retained verdicts. This is data validation;
the standard's form tools remain the publisher's authoring procedure, since derivation can load authored code.

New controller envelopes use schemaVersion 2 and kind `publisher-review`. `prepared` binds the submission,
integrity, registry visibility, source commit, public-package provenance when required, package metadata and
generated facts. `report.publisherReview` retains each of the
four journey/review files with its archive path, exact UTF-8 text and SHA-256. The two verdicts must say plausible
and attribute an independent judge and the authors. Verdict source hashes retain what the judge originally read;
later corrections keep that verdict, so admission does not require its source hash to equal the current file hash.
This record describes a retained publisher review, never an independent catalog execution or a fidelity score.

The input digest, trusted-base policy/source registration, PR head/base and controller source bind the envelope.
Only a separately registered assessment authority can record it in a digest-named durable evidence release.
Release author and asset uploader identities, current-head moderation, immutable artifact identity and publication
custody remain separate requirements. Registry access uses existing credentials; evidence contains none of them.

SchemaVersion 1 envelopes and Actions receipts remain readable under their original provenance, image and lock
rules. Their measured fields keep their original meaning and scope. An existing pinned release needs no new
review, rebuild, version or admission because the controller changes. New records expose publisher review
separately and supply no dynamic measurements. Missing historical evidence stays unavailable.

Catalog-owned native backing facts are authored in `policy.packs`. The builder derives one
`facts/<vendor>.json` containing only `{ "packs": { "<vendor>": <facts> } }` for each safe vendor id. A World passes
only selected vendors' files to the kernel. The whole catalog policy is never a kernel facts input; these files
are generated artifacts, not a second authored inventory.

The catalog owns ecosystem recognition rules, media, released starter requirements and durable report references
in `policy.ecosystem`. Recognition-only vendor records have no package releases. Consumers read their configured
installed catalog; these facts are not platform inventories. Snapshot identity binds the catalog policy as well
as the admission ledger and retained evidence.

Vendor identities are npm package-name components matching `^[a-z0-9][a-z0-9._-]*$`, including numeric prefixes
and dotted service names. Submissions, vendor records and generated facts use that same identity without aliases
or renaming. Source-registration names remain the stricter letter-prefixed hyphenated slugs; they identify a
publisher registration rather than a vendor.
